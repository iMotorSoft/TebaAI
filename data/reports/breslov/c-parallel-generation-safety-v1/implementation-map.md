## Architectural conclusion

No second ingestion/vector/retrieval architecture was introduced. The prior contract's distinct document UUID per approved pipeline version remains binding. A new generation table keyed only to existing run_id would be insufficient because canonical text and chunks are document-owned. A unified active-document pointer/epoch, guarded admission, source/retention repair, common reader authorization and shared lifecycle locking are still required. Existing statuses alone cannot prove safety.

No separate `modules/assistant` exists in the inspected backend modules; the relevant assistant surfaces are the investigative/relation/research implementations above. Frontend consumers (`SourcePanel.svelte`, library source components) already have unrelated user edits and were not modified. Their viewer generation behavior was **not** browser-certified.
